# 桌面界面约定

目标是让用户在表格与企业微信聊天之间持续填写。实现为 PySide6 Qt Widgets，不使用 Web 营销布局、外部字体或在线图标。

## 色彩和字体

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 工作区 | `#F4F6F8` | 主背景，区分表面与留白 |
| 表面 | `#FFFFFF` | 表格、填写区和对话框 |
| 正文 | `#202B33` | 记录、表头和标题 |
| 次要正文 | `#586975` | 帮助、计数、字段说明 |
| 主操作 | `#176B5D` | 聊天跟随、当前选中、焦点 |
| 结构线 | `#DCE3E8` | 表格和区域分割，不承担控制边界 |

系统字体优先 Microsoft YaHei UI，保留中文与高 DPI 支持。正文 13px、辅助信息 12px、记录名 19px、页面标题 22px。主操作和状态文字分别检查对比度，禁用状态用原生 disabled 语义。焦点切换不改变控件尺寸和文字位置。

## 布局和交互

主窗口左侧只导航表格；顶部保留导入、导出与聊天跟随，减少并列主按钮。表格工具靠近表格，联系人设置/打开操作靠近当前记录。填写区保持稳定编辑器与可滚动字段；保存状态贴近记录身份，错误有重试入口。表格列宽和横向滚动沿用，筛选结果在用户重新应用前冻结。

浮窗优先匹配状态和填写空间；识别范围/自动跟随/置顶均有可见标签。等待、已匹配、歧义、保存错误和手动填写既有文本，也有语义色区分。不能因更改颜色而放宽身份匹配或保存失败保护。

使用同一线宽的本地 SVG 图标，文字操作保留可见标签；纯图标必须有 accessibleName 和提示。动画不是完成本任务的必要条件，不新增持续运动。表单使用可见标签和 label buddy，键盘操作保留现有快捷键。空表、无筛选结果和首次使用分别给出下一步操作。

验证主窗口 1400×850 / 980×620、浮窗 350×670 / 290×420，覆盖普通、长标题、空表、筛选空结果和失败状态；用 Qt 渲染及数据/交互测试核对。截图是布局证据，不代表真实企微客户端已验收。

实测 token 对比度：正文/白底 14.44:1、辅助文字/白底 5.69:1、白字/主操作 6.37:1，状态文字/对应底色至少 5.51:1，输入框边界/白底 3.14:1。检查限定为本浅色主题的这些语义配对，不代表所有平台或深色模式已验收。
